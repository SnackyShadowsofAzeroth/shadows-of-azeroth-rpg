## Product and architecture

- M&M: RPG is an offline-first, mobile web RPG delivered through Cloudflare Pages. Client files live in `public/`; Pages API handlers live in `functions/api/`; `worker.mjs` adapts those handlers for local/Workers preview. `public/sw.js` controls offline asset caching. Never put deployment secrets in the repository. The public-facing game name is M&M: RPG; retain legacy package, Cloudflare project, offline cache, and backup identifiers for compatibility.
- The current deployed game and its saves still use legacy Warcraft-inspired rules and content. Existing systems include character creation/progression, campaign choices, combat, arenas, quests/chronicle, equipment, dungeons, crafting, companions, and local saves. Feature modules and their relationships are indexed in the Graphify graph.
- Read `CAMPAIGN_BIBLE.md` for the campaign and quality standards, `DEVELOPMENT_HANDOFF.md` for accumulated implementation history, and `MNM_REWRITE_PLAN.md` for the agreed conversion order and boundaries.
- `MNM_RACE_LORE.md` is the canon reference for the official race descriptions and race/class eligibility. Consult it when creating characters, races, or story content. The race page's Deep Gnome class list is superseded by the later official patch adding Bard.

## Monsters & Memories rewrite status

- The goal is to rebuild the game around the user's Monsters & Memories RPG rules, remove Warcraft-derived setting and terminology from converted content, and preserve offline play and mobile delivery. The user directed us to apply an original M&M-inspired visual system in parallel with rules and content work.
- `public/mnm-rules.js` defines the legacy six-score helper plus the seven M&M stats (STR, STA, DEX, AGI, INT, WIS, CHA), race/class modifiers, d20 checks, character normalization, source-aware ability eligibility, and the level-60 cap. The M&M creator and character record use its race/class matrix and starting-stat calculations. `public/mnm-adventure.js` provides one offline original story chapter and uses the existing d20 helper for checks; its Resolve/Pressure encounter is custom story gameplay, not official M&M combat. `public/mnm-systems.js` adds documentation-backed Combat, Progress, and Items views: ten ability slots, page and spellbook gates, Q auto-attack state, group XP eligibility, the Rested bonus/bank, the documented starting note and candle, container slots, and corpse timers. It deliberately does not simulate attack outcomes, award/threshold XP, weight penalties, or an item catalog. Do not describe the M&M conversion as a complete combat/progression/item simulation.
- The user-directed visual pass lives in `public/mnm-ui.css`. It uses original Night Harbor harbor-at-dusk art, a parchment character-creation desk, compact score rows, and squared iron, wood, and bronze frames. The artwork is original and does not reuse M&M game assets. M&M characters enter the dedicated Adventure/AI Chronicle/World/Character/Journey Log interface; legacy characters retain their existing flow.
- The M&M creator displays seven game stats: Strength, Stamina, Dexterity, Agility, Intelligence, Wisdom, and Charisma. Starting totals use an M&M: RPG baseline of 10 plus the selected race and class modifiers. Character creation grants no extra allocation points for now. This is a deliberate balance change from the M&M score scale; the game-play stat effects still need conversion and tuning.
- New M&M character creation offers only Female and Male; existing saved profile gender values remain unchanged.
- User supplied the racial and class modifier tables. Deep Dwarf, High Elf, and Troll retain inferred provisional modifiers for saved-profile compatibility, but are excluded from new character creation until the user supplies their in-game stat lines. Do not treat those inferred values as confirmed.
- Var'nai remains recognized for old profiles but is not offered for new creation because no in-game modifier line was supplied. Deep Gnome Bard was added to the class matrix from the current official patch note.
- New M&M character sheets store the seven starting stats, race and class modifiers, and lore-reviewed custom racial features. Chapter One has twelve distinct once-per-chapter effects: flexible re-investigation (Human), clue discovery (Gnome), a mapped safe route (Deep Gnome), danger repair (Dwarf), a spirit snare (Deep Dwarf), a one-failure ward (High Elf), a prepared flank (Wood Elf), a clue-enabled stealth strike (Deep Elf), a risky assault (Ogre), peaceful parley (Halfling), a near-escape counter (Troll), and a hidden-route recovery check (Goblin). These are original M&M: RPG story rules, not official M&M racial abilities; preserve the lore links without assigning one personality to an entire race.
- M&M profiles are accepted by roster validation and kept distinct from legacy Warcraft profiles. Their race-defined home is stored as `startingLocation`/`startingZone`; the adventure save tracks `currentLocation` separately from the story's original `origin` so travel never overwrites quest progress.
- M&M profiles start without a Warcraft faction, profession, legacy gear kit, or currency. Their offline chapter, travel, journal, and optional generated Chronicle are saved in `soa-mnm-adventure-v1`; documented M&M system state is saved in `soa-mnm-systems-v1`. Both keys are snapshotted with the active character, included in archive backup/restore, and isolated from legacy campaign state. The system save tracks the guide-documented class guild note and Trainee's Candle, but not unlisted class scrolls or catalog item data. `public/campaign.js` exits before starting its legacy campaign when an M&M character is active. Legacy characters and saves remain available and unchanged.
- `public/mnm-ai-chronicle.js` adds optional Gemini-generated, replayable-by-choice chapters to the M&M mode. It generates three stat-based choices per scene, resolves custom d20 story checks on the device, retains a local journal, and saves per character inside `soa-mnm-adventure-v1`; the fixed chapter remains playable offline. `functions/api/mnm-chronicle.js` validates race/class, region, request size, access code, output shape, and an isolate-local per-IP rate limit before returning narrative. The Gemini key remains server-side. This is original narrative play, not official M&M combat or rewards: AI cannot modify character stats, HP, levels, XP, abilities, currency, inventory, travel, or quest flags.
- Official class abilities must retain their class prefix, name, rank, and source requirements. Level eligibility is not the same as learning: characters must learn official abilities from a trainer or scroll. Keep custom abilities explicitly identified as custom. Gate use by class, level, learned state, target, equipment, reagents, and Mana as applicable.
- Do not guess missing class/rank tables, item catalogs, or progression curves. Deep Dwarf, High Elf, and Troll's inferred provisional modifiers remain for saved-profile compatibility only; these races are excluded from new character creation until the user supplies in-game stat lines. Other missing values still require the user's reference. Preserve legacy saves and distinguish legacy characters from new M&M characters; never silently reinterpret or erase local data.
- Conversion order: official rules/catalogs → expand the playable M&M story/save model → implement balanced combat, class/racial abilities, XP and progression → add quests, itemization, and deeper world content → continue save/offline hardening. The original visual redesign proceeds in parallel.
- Chapter One, `The Quiet Signal at Dune Gate`, is original project story material in the official Aêthoril/Szuur setting frame. Humans, Halflings, Gnomes, and Dwarves begin in Night Harbor in the Shaded Dunes. Deep Gnomes, Deep Elves, Goblins, and Ogres begin in the Underdocks; a lift joins it to Night Harbor. Wood Elves begin in Penshaw in Keeper's Blight. All races can sail from Twilight Harbor in Night Harbor to Penshaw. Deep Dwarf, High Elf, and Troll profiles use the accepted Night Harbor fallback but remain unavailable for new creation until their in-game stats are supplied. The chapter's d20 checks, one-use racial story traits, and Resolve/Pressure encounter are custom story rules; it gives no XP, items, or currency.

Refresh it after future code edits and keep `graphify-out/graph.json` and `GRAPH_REPORT.md` current.

### Character creation availability
The M&M creator must treat an omitted race `selectable` flag as available and only reject a race when the flag is explicitly `false`. The regression is covered by `isSelectableRace` tests for supported and withheld races.
