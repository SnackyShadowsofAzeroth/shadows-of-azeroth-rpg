## Product and architecture

- M&M: RPG is an offline-first mobile web RPG delivered through Cloudflare Pages. Client files live in public/; Pages API handlers live in functions/api/; worker.mjs adapts those handlers for local/Workers preview; public/sw.js controls offline asset caching. Never put deployment secrets in the repository.
- Character rosters, adventure saves, and portraits are stored locally in the current browser/device; they do not sync between devices. The character selector distinguishes the saved roster from an unfinished creation draft, labels the commit action “Save Character & Play,” verifies localStorage writes by reading them back, cleans up failed creation slots before rollback, and shows a success message after creation.
- M&M character selection is M&M-only. Startup removes legacy roster entries and their save slots, clears orphaned shared legacy save keys, and never seeds the old default character. Existing M&M profiles and their character-bound data remain intact.
- M&M profiles use a separate seven-stat creator, race-specific starts, world travel, a saved AI-generated or local procedural campaign in the Adventure view, city-based Arena access through World travel, and character-bound system saves. When an active encounter blocks movement, the World view shows the foe and a direct Combat action so players can continue or escape.
- Read CAMPAIGN_BIBLE.md for campaign and quality standards, DEVELOPMENT_HANDOFF.md for implementation history, and MNM_REWRITE_PLAN.md for conversion scope.
- M&M race descriptions and eligibility come from MNM_RACE_LORE.md, with Deep Gnome Bard updated from the later official patch note.

## M&M character rules

- public/mnm-rules.js defines STR, STA, DEX, AGI, INT, WIS, CHA, the user-supplied race/class modifiers, d20 checks, character normalization, and the level-60 cap.
- The M&M creator starts scores at 10 plus selected race and class modifiers. It grants no extra allocation points. This is an intentional M&M: RPG rebalance, not official score-scale parity.
- New character creation offers Female and Male. Existing saved gender values are preserved.
- The user supplied stat lines for the playable races and classes. Deep Dwarf, High Elf, and Troll use inferred provisional values only for older-profile compatibility; keep them excluded from new character creation until their in-game stat lines are supplied. Var'nai remains available only to old profiles because no stat line was supplied.
- Starting homes: Human, Halfling, Gnome, Dwarf → Night Harbor; Deep Gnome, Deep Elf, Goblin, Ogre → the Underdocks; Wood Elf → Penshaw in Keepers Bight as a custom M&M: RPG start assignment. The Underdocks lift links to Night Harbor. All races can sail from Twilight Harbor in Night Harbor to Penshaw. Existing Deep Dwarf, High Elf, and Troll profiles use Night Harbor fallback.
- Racial features remain original project abilities: keep them lore-aware, generalized, and clearly labeled as custom; their displayed descriptions must not mention specific quest items or props. Their effect text must match implemented story and turn-based actions, use current mechanics such as d20 checks, Health, Focus, Defense, damage, recovery, safe routes, and parley, and never refer to retired Danger/Resolve counters. Do not call racial features official M&M abilities. Combat no longer generates made-up class techniques.
- The M&M adventure uses eight view tabs: an eight-column row on wide screens and a four-column grid on phone/tablet widths. Keep tab labels centered and wrapping only at spaces.
- UI direction: use a warm dune palette of parchment, sandstone, bronze, and terracotta; avoid broad green accents. Keep the Night Harbor art visible and use the official M&M site for layout inspiration rather than copying its branding or assets. Text over dark setting art and dark choice cards should use light, high-contrast copy; stat and difficulty labels on choice cards should be legible at phone sizes. Text on parchment surfaces should use dark ink. Racial-feature callouts remain charcoal-and-bronze inset panels so their light copy keeps strong contrast against the parchment creator; exclude them from the parchment callout override. On character records, generic `.panel` heading and paragraph rules can override nested copy, so `.soa-mnm-racial-ability` needs explicit light text colors inside panels.

## Playable custom rules and official facts

- On 2026-11-13 the user explicitly authorized clearly labeled original custom combat, leveling, and item rules when official formulas or catalogs are unavailable. Confirmed M&M facts and project house rules must remain clearly separate.
- public/mnm-systems.js provides a deliberate turn-based custom d20 loop. Each player action advances one round; the foe telegraphs a quick strike, heavy windup, guard, or recovery before the player chooses. Strike, Feint, Guard, learned and memorized verified abilities, consumables, Rogue Stealth, and escape each have explicit local outcomes. Feint costs 1 custom Focus; a success exposes the foe and interrupts a telegraphed non-strike move. Guard raises Defense and halves the next hit. No timer or keyboard shortcut performs attacks. Legacy auto-attack flags are disabled during save migration. Encounter logs retain player and foe outcomes so the AI Chronicle can carry real combat consequences into later scenes. Verified memorized M&M abilities use separate, clearly labeled custom dice resolution; Rogue Backstab uses a Stealth check and doubles the custom weapon bonus on a successful opening, while Archer Point Blank is seeded as a verified starter skill. Other classes have no invented technique stand-ins until their ability records are verified. Class ability records do not receive invented Focus costs; foes are selected from regional custom tables; victory awards custom XP and Platinum, Gold, Silver, and Copper coinage using the 100:1 exchange; levels improve Health and Focus; the player can claim one-time rewards for completed AI campaign chapters; items can be equipped, used, sold, bought, or discarded; carry limits, safe rests, and location-aware corpse recovery are custom. Once-per-chapter racial combat tactics now consume the same player turn and let the foe respond, except for a successful parley.

- All combat math, foe values, custom item definitions and weights, prices, carry limits, XP thresholds and rewards, healing amounts, rest healing, and custom racial/class mechanics are original M&M: RPG house rules. Do not present them as official M&M values.
- Official guide-backed mechanics remain source-linked: the MMO guide documents auto-attack controls, but this RPG adapts combat to deliberate player-selected turns; learned/memorized abilities use ten slots and page/spellbook rules; group XP has documented eligibility constraints; Rested XP has a 15% bonus and a 20-minute bank; the guide documents a guild note, candle, bag/belt slots, corpse recovery, and weight-based encumbrance. Some exact official rates and formulas remain unpublished. All attack cadence and intent rules belong to the custom turn-based adaptation.
- Official class abilities must preserve class prefix, name, rank, source, and learned requirements. Combat accepts only learned, memorized, class-matching official records; custom M&M: RPG d20 resolution is kept separate from official ability descriptions. public/class-abilities.js is a legacy non-M&M catalog and must never supply M&M class skills. Official level tables are incomplete in available sources; do not invent unlock levels.
- The level-60 cap is documented, but this project uses an original XP curve. AI-generated and local campaign chapters may give player-claimed custom XP; AI cannot alter a character sheet or reward state. A local campaign works without AI credentials or service, while the connected AI Chronicle remains available when configured. Local World travel, Arena bouts, combat, inventory, and saves also work without AI scenes.
- The official M&M New Player Guide is at monstersandmemories.com/new-player-guide. Official XP and weight FAQs are at account2.monstersandmemories.com/community/faqs/15 and /45. The Miraheze wiki was unavailable to the prior request (HTTP 403); do not claim its pages were reviewed unless accessible.

## Save, AI, and offline behavior

- M&M profiles receive a road-worn weapon, patched travel coat, two healing poultices, two waybread, and 24 Copper. They do not receive legacy faction, professions, legacy equipment, or legacy currency.
- M&M coinage is stored as an integer Copper balance and displayed as Platinum, Gold, Silver, and Copper. Each 100 lower-denomination coins convert to one coin of the next denomination; preserve the existing `coppers` save property.
- An empty M&M roster stays empty until the player creates a character. The selector permits deleting the last character, removes that character's saves, and accepts only M&M character archives for restore.
- The adventure, world travel, AI Chronicle, and journal use soa-mnm-adventure-v1; official-rule and custom RPG system state uses soa-mnm-systems-v1. Both keys participate in character switching, archive backup/restore, and local saves. Adventure data uses schema version 3 under the existing key; v1/v2 migration preserves the journal, AI campaign, and claimed rewards, retires fixed-chapter state, and defaults prior characters to their city streets. Current city site, arena visit state, bout record, and active arena combat link are saved per character.
- public/mnm-ai-chronicle.js supports two saved story paths. The AI Chronicle generates connected scenes with three choices plus a player-written action through Gemini; its recent action ledger, completed/paused chapter summaries, unresolved threads, current character resources, combat outcomes, and learned official abilities guide continuity. AI cannot alter game mechanics. AI requests require the Cloudflare GEMINI_API_KEY and AI_ACCESS_CODE. The local campaign selects original regional arcs, resolves four saved d20 decisions with success/setback branches, records journal and campaign outcomes, and allows optional custom XP claims without any network dependency. If an AI scene request fails, the saved action and die remain intact and can continue locally. Both paths keep rewards optional and preserve character-bound saves.
- public/sw.js cache version must be incremented when cached gameplay files change. The current source version is mm-rpg-v167; activation removes superseded M&M caches and the prior cache namespace.
- The M&M character gate must not run the legacy mobile tab controller: with no selected M&M character, that controller can unhide the prototype status and story panels. M&M characters and saves are scoped to the browser and exact website origin; preview and production hosts have separate storage, and Private Browsing may discard local data when the session ends.
- Preserve existing M&M characters and saves during roster cleanup; do not reintroduce legacy profiles into M&M selection or restore.
