## Product and architecture

- Shadows of Azeroth is an offline-first, mobile web RPG delivered through Cloudflare Pages. Client files live in `public/`; Pages API handlers live in `functions/api/`; `worker.mjs` adapts those handlers for local/Workers preview. `public/sw.js` controls offline asset caching. Never put deployment secrets in the repository.
- The current deployed game and its saves still use the legacy Warcraft-inspired rules and content. Existing systems include character creation/progression, campaign choices, combat, arenas, quests/chronicle, equipment, dungeons, crafting, companions, and local saves. Feature modules and their relationships are indexed in the Graphify graph.
- Read `CAMPAIGN_BIBLE.md` for the campaign and quality standards, `DEVELOPMENT_HANDOFF.md` for accumulated implementation history, and `MNM_REWRITE_PLAN.md` for the agreed conversion order and boundaries.

- `MNM_RACE_LORE.md` is the canon reference for the official race descriptions and race/class eligibility. Consult it when creating characters, races, or story content. The race page's Deep Gnome class list is superseded by the later official patch adding Bard.

## Monsters & Memories rewrite status

- The goal is to rebuild the game around the user's Monsters & Memories RPG rules, remove Warcraft-derived setting and terminology from converted content, and preserve offline play and mobile delivery. The user directed us to apply an original M&M-inspired visual system in parallel with rules and content work.
- `public/mnm-rules.js` defines the legacy six-score helper plus the seven M&M stats (STR, STA, DEX, AGI, INT, WIS, CHA), race/class modifiers, d20 checks, character normalization, source-aware ability eligibility, and the level-60 cap. The M&M creator and character record use its race/class matrix and starting-stat calculations. `public/mnm-adventure.js` provides one offline original story chapter and uses the existing d20 helper for checks; its Resolve/Pressure encounter is custom story gameplay, not official M&M combat. `public/mnm-systems.js` adds documentation-backed Combat, Progress, and Items views: ten ability slots, page and spellbook gates, Q auto-attack state, group XP eligibility, the Rested bonus/bank, the documented starting note and candle, container slots, and corpse timers. It deliberately does not simulate attack outcomes, award/threshold XP, weight penalties, or an item catalog. Do not describe the M&M conversion as a complete combat/progression/item simulation.
- The user-directed visual pass lives in `public/mnm-ui.css`. It uses an original illustrated frontier landscape, a parchment character-creation desk, compact score rows, and squared iron, wood, and bronze frames. The artwork is original and does not reuse M&M game assets. M&M characters now enter the dedicated Adventure/Character/Journey Log interface; legacy characters retain their existing flow.
- The M&M creator displays seven game stats: Strength, Stamina, Dexterity, Agility, Intelligence, Wisdom, and Charisma. Starting totals use a Shadows of Azeroth baseline of 10 plus the selected race and class modifiers. Character creation grants no extra allocation points for now. This is a deliberate balance change from the M&M score scale; the game-play stat effects still need conversion and tuning.
- User supplied the racial and class modifier tables. Troll, High Elf, and Deep Dwarf use explicitly marked provisional modifiers, each kept to the same +2 total racial modifier pattern as the supplied races.
- Var'nai remains recognized for old profiles but is not offered for new creation because no in-game modifier line was supplied. Deep Gnome Bard was added to the class matrix from the current official patch note.
- New M&M character sheets store the seven starting stats, race and class modifiers, and lore-reviewed custom racial features. Chapter One replaces the shared +1 check bonus with twelve distinct once-per-chapter effects: flexible re-investigation (Human), clue discovery (Gnome), a mapped safe route (Deep Gnome), danger repair (Dwarf), a spirit snare (Deep Dwarf), a one-failure ward (High Elf), a prepared flank (Wood Elf), a clue-enabled stealth strike (Deep Elf), a risky assault (Ogre), peaceful parley (Halfling), a near-escape counter (Troll), and a hidden-route recovery check (Goblin). These are original Shadows of Azeroth story rules, not official M&M racial abilities; preserve the lore links without assigning one personality to an entire race.
- M&M profiles are accepted by roster validation and kept distinct from legacy Warcraft profiles. Their race-defined home is stored as `startingLocation`/`startingZone`; the adventure save tracks `currentLocation` separately from the story's original `origin` so travel never overwrites quest progress.
- M&M profiles start without a Warcraft faction, profession, legacy gear kit, or currency. Their story progress is saved in `soa-mnm-adventure-v1`; documented M&M system state is saved in `soa-mnm-systems-v1`. Both keys are snapshotted with the active character, included in archive backup/restore, and isolated from legacy campaign state. The system save tracks the guide-documented class guild note and Trainee's Candle, but not unlisted class scrolls or catalog item data. `public/campaign.js` exits before starting its legacy campaign when an M&M character is active. Legacy characters and saves remain available and unchanged.
- Official class abilities must retain their class prefix, name, rank, and source requirements. Level eligibility is not the same as learning: characters must learn official abilities from a trainer or scroll. Keep custom abilities explicitly identified as custom. Gate use by class, level, learned state, target, equipment, reagents, and Mana as applicable.
- Do not guess missing class/rank tables, item catalogs, or progression curves. The user explicitly authorized logical provisional modifiers for Troll, High Elf, and Deep Dwarf; keep those labels visible. Other missing values still require the user's reference. Preserve legacy saves and distinguish legacy characters from new M&M characters; never silently reinterpret or erase local data.
- Conversion order: official rules/catalogs → expand the playable M&M story/save model → implement balanced combat, class/racial abilities, XP and progression → add quests, itemization, and deeper world content → continue save/offline hardening. The original visual redesign proceeds in parallel.

## Graphify workflow

- Graphify is installed as a project-scoped Codex skill under `.codex/skills/graphify/`, with project guidance in `AGENTS.md` and a Codex hook in `.codex/hooks.json`.
- The checked-in graph is the compact navigation index for the codebase. Query it before inspecting code; use `graphify path` and `graphify explain` for focused questions. Treat inferred graph edges as leads and verify them in source.
- Install the CLI with `uv tool install graphifyy` if it is unavailable. The executable is `graphify`.

Refresh it after future code edits and keep `graphify-out/graph.json` and `GRAPH_REPORT.md` current.

- Chapter One, `The Quiet Signal at Dune Gate`, is original project story material in the official Aêthoril/Szuur setting frame. Starting homes are race-specific: Human, Halfling, Gnome, Dwarf, Deep Dwarf, High Elf, and Troll begin in Night Harbor in the Shaded Dunes; Deep Gnome, Deep Elf, Goblin, and Ogre begin in the Underdocks; Wood Elves begin in Penshaw in Keeper's Blight. Deep Dwarf, High Elf, and Troll use the user's accepted Night Harbor fallback until separate homes are defined. Night Harbor's Twilight Harbor boats to Penshaw for every race, and a lift joins the Underdocks to Night Harbor. The World view persists travel independently from story progress; older unstarted origin saves migrate once to the race's assigned home while active stories keep their location. Official faith/deity-based city eligibility is not modeled because the creator has no faith selector. The chapter's d20 checks, one-use racial story traits, and Resolve/Pressure encounter are custom story rules; it gives no XP, items, or currency.
